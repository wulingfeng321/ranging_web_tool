# RNG1 格式与分析依据

## 解析器来源

`backend/app/legacy_decoder.py` 是现有工具 `tools/decode_capture.py` 的原样快照。来源工程 HEAD：`c1c9eddd1cc48ea041c72624a54b346a7b35e2ea`。复制文件 SHA-256：`7675be497af2462651f4ac7ec8a3e3848b8d1e28e010292bf0fb32f697242052`。工作区文件为直接来源，后续同步需核对实际文件差异和样本回归，不能仅凭 HEAD 判断内容。

文件依次包含：4096 字节 NUL 填充 JSON、16 位小端双声道 PCM、24 字节锚点数组、ASCII CSV 日志。锚点 `<QQII>` 为绝对样本末位置、本地块末 ns、audio epoch、块帧数。完整标记包含 A/B 字节数和 FNV-1a 校验值。

日志字段的精确顺序来自上述快照的 `SCHEMAS`。未知或字段数不符的日志使解析失败，不静默跳过。

## 事件关联

已核对 `app_range.c::DetectionReady` 与配对记录写入位置：

- `event.event` 是本地检测计数。
- `clock.event` 与 `candidate.event` 使用同一本地检测计数。
- `pair.event_a_id / event_b_id` 来自通信序号，与本地检测计数不同。
- `pair.a_master_ns / b_master_ns` 可与 `clock.master_ns` 精确匹配；只接受唯一匹配。
- `candidate.index_zero_based` 从 0 开始，而 `pair.best_a/b` 和 runner 候选编号从 1 开始。
- B 候选偏移保留本地时钟定义；固件传输会做时钟转换和量化。因此界面显示记录的配对评分，不使用原始候选直接声称复现固件评分。

配对 reason 的当前定义：0 唯一配对、1 次佳候选过于接近、2 候选溢出、3 脉冲间时差不一致、4 候选数量无效。历史固件若改变定义，需增加版本化映射。

## 时间处理

A 的本地时钟为主时间基准。块内采样间隔优先使用同 epoch、绝对样本计数连续的相邻块末锚点差；首块或断点后采用名义采样间隔，且断点不连线。异常块间隔回退名义间隔并标为断点。相对时间基准为 A 的第一块起点估计。

B 使用相邻锁定事件的 local/master 时间对作线性插值，要求同一有效音频 epoch、无块断点、事件间距 ≤1.1 s、映射斜率偏离 1 小于 0.001。阈值是首版保守显示策略，不是固件锁定判据。范围外不外推；长间隔切断连线。后续如需验证微秒级差异，应使用已验证的音频时钟拟合方法，并给出残差与不确定度。

tick_ms 与主时钟缺少逐点对应证据，因此状态图独立展示。封存元数据是采集结束时快照，不用其简单偏移外推整段历史。

## 指标口径

唯一配对数：A 的 pair 日志 outcome=1 条数。歧义数：outcome=2。不一致数：outcome=0。分母为记录的 pair 总数，不等同于发射总数或测距成功率。

距离均值/总体标准差：仅使用 outcome=1 且存在有效最佳评分的时差换算距离。采用封存温度和零固定偏置，保留小数，不复刻固件整数舍入或后续批次滤波。真实距离由用户人工填写；误差比较针对这一换算量。

## 样本检查

`sample-audit.json` 记录 28 轮原始数据的只读校验与解析结果、字段计数、代表记录及 PCM SHA-256。全部通过当前解析器，但这并不意味着所有历史数据对应相同实验条件或算法配置。

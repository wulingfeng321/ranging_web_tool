# 本地第一版验证记录

日期：2026-10-23。环境：Windows、Python 3.13.15、Node.js 24.21.0。

## 已完成验证

- 28 轮真实采集全部通过完成标记、文件长度、FNV-1a、RNG1 格式与日志结构检查，详见 sample-audit.json。
- 28 轮共 400 条配对全部通过 A/B 主时钟精确匹配，均能唯一关联本地事件；生成的四通道波形时间有序、幅值在 int16 范围内，详见 validation-samples.json。
- 后端 11 项测试：协议序号与本地事件关联、校验损坏、缺少标记、极值包络、禁止时钟外推、未锁定与 epoch 断点、原解析器数据一致性、重复时钟不猜测、未知日志与截断拒绝、超大时间戳平移不改变相对采样，以及 API 导入/更新/导出/失败处理。
- 前端 TypeScript 检查与生产构建通过。
- 浏览器已验证：真实实验切换、事件表点击与波形缩放联动、候选详情、同步误差图、固件显示距离图，以及两轮真实实验的箱线分布比较。
- 本地启动器已实际启动单个后端进程，同时提供构建后的网页与 API，数据库中的实验在重启后保留。
- 浏览器实际选择 R000004 的三个原始文件并上传，完成自动解析，显示 15 条配对、14 条唯一配对和 1 条歧义配对。点击歧义记录后正确显示最佳/次佳评分及关联波形；运行截图保存在 screenshots/。

## 验证时发现并修复

- 配对协议序号不能直接关联本地事件编号，改为匹配 clock.master_ns。
- 状态 tick_ms 不能直接用作主时钟时间，单独显示。
- 浏览器对大整数不能保证精度，原始日志保持字符串，大整数元数据序列化为字符串。
- NumPy 音频概览采用极值包络，避免直接抽点漏掉窄峰。
- 本机环境代理曾影响本地脚本连接；样本导入脚本显式不使用环境代理，只连接指定的本地 API。
- 浏览器检查发现 Plotly basic 构建不包含箱线图模块，会退化为散点折线；改用包含统计图的 Cartesian 构建。

## 限制

- 本地测试通过不代表 Linux 实机验证；未连接云服务器。
- 首版只监听 127.0.0.1，没有公网认证。不作为已完成的公网部署交付。
- B 音频的主时钟映射是有限区间内的诊断插值，尚未验证采样级时钟拟合精度；不可据此直接声称微秒级同步准确度。
- 样本真实距离未从目录名自动填写，误差指标需用户核实实验条件后使用。
- 当前测试依赖发出 httpx 迁移弃用提示，测试通过；前端构建提示图表依赖较大，后续部署可开启 gzip 并缓存静态资源。
- ZIP、文件夹上传、实验删除、完整频谱与算法复算尚未实现。

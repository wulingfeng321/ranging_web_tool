# Ranging Studio · 测距实验分析

使用 React / Plotly.js 展示实验数据，FastAPI 校验、分析 RNG1 采集，SQLite 保存实验记录。支持 Windows 本地运行，已部署到腾讯云 Ubuntu 24.04。

云端地址：**https://ranging.wulingfeng.top**（需要网站访问密码）。已迁移 10 轮实验与 4 条 AI 分析记录；本地和云端后续数据各自独立。部署、备份和配置方法见 [服务器维护说明](docs/server-deployment.md)。

## 启动

当前电脑已经安装项目依赖并生成前端构建。双击项目根目录的 **`start-local.cmd`**，浏览器会打开 **http://127.0.0.1:8000**。

保持启动窗口运行；在窗口按 Ctrl+C 停止服务。本地启动器只监听本机；云端通过 Nginx 提供 HTTPS 和全站密码保护，不要将后端 8000 端口直接开放到公网。

## 怎么使用

1. 点击“导入实验”，一次选择同一轮的 `A.RNG`、`B.RNG`、`COMPLETE.TXT`。也可以将三个文件拖入上传框。
2. 填写名称、备注；真实距离可选，单位为 mm。
3. 完成校验后，查看配对曲线与音频。点击图中点或表格行，会同时放大时间范围并显示候选详情。
4. 波形可切换 A/B 的两个通道；拖动框选缩放，双击或点击“全览”复位。悬停图表可使用工具栏导出 PNG。
   波形上方的 A/B 两行三角标记表示各板检出事件，虚线对应检出时刻；悬停显示本地事件号与时间，点击放大附近并关联配对详情。“检出事件”开关可隐藏标记。主时钟模式下，已关联且两板均锁定的配对显示检出时差 B−A（负值表示 B 先检出），该值与候选组合的最佳配对时差分别展示。本地录音时间模式不能直接比较两板传播时差；无主时钟映射的事件在本地模式查看。
5. “时钟与采集状态”展示同步误差、音频计数及固件实际显示距离；其时间轴使用各板 tick，不与音频主时钟强行联动。
6. “解析数据”按 A/B 板展示文件元数据、全部日志、音频锚点、PCM 逐帧数据及各类检测、时钟、配对、状态记录。支持分页、跳页和点击记录展开全部字段；“导出本类全部 CSV”导出完整分类，不限于当前页。
7. 同一页的“接收音频”支持 A/B 板播放、暂停、拖动进度，以及双声道、CH1、CH2 切换和无损 WAV 下载。播放一板时自动暂停另一板；播放起点为各板录音起点，不表示同步播放。
8. “实验对比”最多选择四轮，对比换算距离分布。填写真实距离后可查看偏差、MAE 和 RMSE。
9. 页面顶部“导出 CSV”导出配对记录、原始协议编号、匹配的本地事件编号与分析条件。
10. “AI 分析”支持 DeepSeek 测量汇总、异常诊断和实验报告。先在 `config/ai.local.toml` 填写 API Key 并启用，再刷新配置。可预览发送材料、补充分析重点、查看历史和导出报告。详见 [AI 配置与数据范围](docs/ai-analysis.md)。

事件详情与图表区在宽屏各占一半，在较窄窗口上下等宽排列；详情文字已放大并提高对比度，候选同时显示三个脉冲偏移与质量。

初始导入了四轮真实样本供体验，其中 R000004 通过网页上传完整验证，后续可继续添加实验。原始样本目录未被改动，项目的 `data/` 中保存独立副本及音频缓存；这部分不进入 Git。已有实验可以直接使用新功能，无需重新导入。

## 如何解读

- **唯一配对 ≠ 最终测距通过**：pair.outcome 只反映候选配对结果，固件还可能执行距离拒绝或批次统计。
- **换算距离**为 `abs(best_ns) × (331.3 + 0.606 × 封存温度°C) / 1e6` mm，假设固定偏置为零。它不冒充固件最终输出；历史实验若温度在采集期间改变，封存温度可能不代表每个事件。
- 配对记录中的 `event_a_id/event_b_id` 是通信序号。本地事件依赖 `pair.*_master_ns == clock.master_ns` 唯一匹配，再通过本地事件号关联 candidate。
- A 音频使用块末锚点建立时间。B 音频在同 epoch、无断流、两端锁定且间隔不超过 1.1 s 的事件间进行诊断性线性插值，并使用记录的时钟模型补齐事件前 100 ms / 后 160 ms 的局部波形，避免末次脉冲被起点裁断。补齐只覆盖同一连续采集段；它不是采样级同步精度保证，其余未知范围留空。
- “各板录音时间”模式可查看全段 B 音频，但 A/B 起点各自归零，不能用于判断传播时差。
- 原始纳秒时间和日志数值保留为字符串；大整数元数据亦转换为字符串，避免浏览器精度丢失。
- 图表概览保留极值。距离统计由日志原值计算，不使用音频抽稀点。

## 开发与测试

首次在新电脑准备环境：

```powershell
python -m venv backend/.venv
.\backend\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
cd frontend
npm.cmd ci
npm.cmd run build
```

开发时分别打开两个终端：

```powershell
# 项目根目录
.\backend\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

```powershell
# frontend 目录，开发地址 http://127.0.0.1:5173
npm.cmd run dev
```

后端测试：在 `backend/` 执行 `.\.venv\Scripts\python.exe -m pytest tests -q`。测试使用隔离的临时数据库，不写入正式 `data/`。

只读审计样本：`python scripts/audit_samples.py <样本根目录>`。

通过本地 API 导入代表样本：`.\backend\.venv\Scripts\python.exe scripts/import_samples.py <样本根目录> --limit 3`。使用 `--limit 0` 导入全部；按实验名称跳过已有导入，不自动推定真实距离。

`RANGING_DATA_DIR` 可指定独立数据目录。SQLite、原始文件与报告均位于该目录；部署前应制定备份和认证方案。
